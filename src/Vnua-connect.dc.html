State transitions

  • Membership: none → joined → left (history retained per policy) · officer role granted/revoked per club.
  • RSVP: none → going → cancelled → going. Event cancel/reschedule leaves RSVP, flags “changed”.
  • Event: scheduled → rescheduled (same ID, original time kept) → cancelled · past after end.
  • Attendance: recorded → corrected (new row linked to reason + actor + time, original kept).
  • Founder invite: pending → accepted | declined | expired. Slots require 4 distinct accounts.
  • Club: draft → submitted → revision requested | published → paused | removed (reason always stored).
  • Leadership: transfer requested → accepted | declined | expired; last admin cannot be removed.

QR / check-in server requirements

  • Payload is an opaque random token, short-lived (e.g. 30–60 s), bound server-side to event and account. No name, email, ID or role in payload.
  • Server validates token, event match, officer/scanner permission for that event, duplicate status, and returns one of: Recorded · Already checked in · Expired · Wrong event · Unauthorized · Connection failure/Not confirmed.
  • Client request ID makes retry idempotent. UI shows “recorded” only after commit.
  • Manual lookup and guest records are first-class and clearly separate.
  • Rate limiting, audit log of scans, token revocation on RSVP cancel or role change.

Export rules

Officer-of-club only; confirmation names club, date range, fields. Default fields exclude email and student ID. Corrections are reflected; export count must equal valid records. Guest rows flagged. Exports are logged. Sponsor reports are aggregated and reviewed only; include RSVP and attendance separately, unique attendees, an explicit reporting window, and feedback response count with denominator. No claim that the app caused engagement.

Validation & failure behavior

  • Errors are text, linked via aria-describedby, announced via role=alert; never color alone.
  • Code: expired → resend; wrong → inline retry; resend delay; wrong email path; delivery failure → help route.
  • Network failure on write → “Not confirmed” with safe retry; no optimistic success.
  • Account deletion: confirmation, explanation of what is removed vs retained in club audit records (retention period is an open decision).

Accessibility annotations (targets)

  • Calendar is a day strip plus a readable list; buttons carry full-date labels and aria-pressed; “Today” is text, not only color.
  • Status changes announced by role=status/alert. Landmarks: header, main, nav. Focus ring never removed.
  • No drag-only interaction. Timed QR has manual alternative. Sign-in uses email code, no cognitive puzzle.
  • Reduced motion respected; no intro animation. Layout reflows to 320px; text resize to 200% to be tested.
  • Native apps, if built later, need separate platform accessibility specs (points ≠ CSS px).

Proposed pilot targets (not results)

  • First-time member finds a fitting club and its next event unaided (proposed ≤ 3 min).
  • Member RSVPs/cancels and explains status correctly (≤ 1 min).
  • Officer records attendance and recovers from a duplicate scan (≤ 30 s per attendee).
  • Manual check-in works with camera denied; export matches records exactly; cross-club access denied.
  • Founder explains why a club is a draft; users distinguish publication from recognition; second officer completes handover from docs.

Acceptance tests (sample)

  1. Officer of club A requests club B attendance by direct URL/API → 403.
  2. Scanner for joint event reads only that event’s check-in fields.
  3. Replayed token returns “Already checked in”; expired token rejected.
  4. Correction retains original + reason; export reflects it.
  5. Sole admin cannot delete account or leave without accepted transfer.
  6. One account cannot fill two founder slots.

Run locally

  1. Download the project folder. It needs Vnua-connect.dc.html, support.js, vnua-mock-api.js, vnua-selftest.js and _ds/.
  2. From that folder, run python3 -m http.server 8000.
  3. Open http://localhost:8000/Vnua-connect.dc.html.
  4. In the browser console, run await vnuaSelfTest(). It resets the prototype.
  5. The QR library and fonts load from public CDNs, so the first load needs a network connection.
